# Nyxa Network

The public website for **Nyxa Network** ([nyxa.cash](https://nyxa.cash)), a private payment pool named for Nyx. This repository is the site only. It is not the protocol, and it does not contain contracts.

Nyxa is in development. The tagline is “Pay in the dark. Leave no trace.” That is the aim of the design, not a claim about a system you can use today.

## Status

- Smart contracts are **not deployed**.
- The app at `/app/` can connect an EIP-1193 wallet (MetaMask, Rabby, OKX Wallet, and other injected wallets) and read the **real** account, network, and native balance. Veil, Whisper, Eclipse, and Crossing forms validate input. Their buttons stay disabled and read **Launching soon**. The page does not submit a transaction.
- **$NYXA** is not launched. No contract address is published here. The address will be announced only on official channels.
- No audit is claimed.
- There is no official X account. The only profile linked from the site is the GitHub repository in the footer: [github.com/nyxaagent-max/nyxa](https://github.com/nyxaagent-max/nyxa).

The site does not show invented balances, totals, user counts, testimonials, partners, or transactions. Diagrams are labelled as illustrations of how the flow is planned to work.

## Product names

| Name | Plan |
| --- | --- |
| Veil | Deposit ETH, USDC, or USDG as an encrypted note |
| Whisper | Private send; a relayer pays gas |
| Eclipse | Private swap inside the pool |
| Crossing | Private move across Robinhood Chain, Base, Arbitrum, and BNB Chain, with Solana as a destination |
| Dawn | Recovery from the wallet signature that created a note |
| Agents | A future CLI and API |

## Pages

Home, Veil, Whisper, Eclipse, Crossing, Dawn, Agents, How it works, Chains, Docs, FAQ, $NYXA, and `/app/`.

Docs describe the planned architecture only: proofs built in the browser, a relayer, Merkle-tree notes, and a non-custodial design. They are not a specification freeze and not an audit.

## Local preview

Root-relative links need a local server.

```bash
python3 -m http.server 4173
```

Open `http://localhost:4173`.

Page shells are generated by `scripts/render.mjs` so the header and footer stay consistent. Edit that script, then run:

```bash
node scripts/render.mjs
```

The committed HTML, CSS, and JavaScript are what GitHub Pages serves. A build step is not required to view or deploy the site.

## Deployment

`CNAME` contains `nyxa.cash`. The workflow `.github/workflows/pages.yml` deploys the site to GitHub Pages when `main` changes.

In the repository settings, set **Pages → Source** to **GitHub Actions**.
